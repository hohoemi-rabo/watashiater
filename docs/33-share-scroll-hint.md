# 33. 閲覧Web：「下にもあります」の案内（下へスワイプしたくなるUI）

## 目的

**家族が URL で開く閲覧Web**（`/w/[slug]`）は「表紙 → ギャラリー → じぶん史 → お題」と縦に長く、
下に続きがあることに気づかない。下へスワイプしたくなる案内を置く。

## 対象画面の取り違え（2026-09-12）

当初このチケットは**アプリの「みんなに見せる」画面**を対象に書かれ、そのとおり実装したが、
ユーザーの意図は**閲覧Web**（リンクを開いたページ）だった。アプリ側の実装は取り下げて元に戻し
（コミット `d560873` の内容を差し戻し）、対象を閲覧Web に変更した。
アプリの「みんなに見せる」に案内は**置かない**（2026-09-12 ユーザー判断）。

実装を戻す際、実機で分かったことだけは残した → CLAUDE.md「`SafeAreaView` の余白は絶対配置の子に効かない」。

## 決定事項（2026-09-12 ユーザー確認済み）

- 対象は**閲覧Web だけ**。アプリ内の家族向け画面（`/family/*`）にも置かない
- **今の錠剤ボタンのデザインは不採用**：白いカードの上では枠を付けても見づらく、おしゃれでない
- **指が下へスワイプするアニメーション**にする。「下にもあります」の文字は添えてよい
- ねらいは「下へスワイプしたくなる」こと

## 見た目の決定（2026-09-12。3案を実機で見くらべて選定）

動きは静止画で判断できないので、空グラデの上に白いカードを重ねた実物大のサンプルを3案つくって
スマホで見くらべてもらった（A=濃紺の丸に白い指／B=指と点線の軌跡だけ／C=すりガラスの錠剤）。

**採用は A**。白いカードに重なっても確実に読めることを優先した。
`stage-navy` の丸（48px）に白い指（lucide `Pointer`）＋`shadow-raised`、下に `stage-navy` の文字
「下にもあります」。

- **ループは3回で止める**：しぐさを伝えるには繰り返しが要るが、ページが延々とちらつくのは避ける。
  DESIGN §8「装飾アニメの常時ループ禁止」の唯一の例外として本書に明記した
- **丸は64px・指は32px**（2026-09-12 実機で「もう少し手を大きく」の指摘を受けて 48/24 から拡大）
- **消えるのはページの終わりが見えてから**（同上）。当初は「40px スクロールしたら消す」にしていたが、
  まだ半分も見ていないのに案内が無くなってしまった。ページの長さは写真や回答の数で変わるため、
  固定 px ではなく**残りが画面の高さの6割を切ったら消す**（`NEAR_BOTTOM_RATIO`）で測る
- `prefers-reduced-motion` ではアニメを止め、静止した指と文字だけを出す
- 押すと1画面ぶん近く下へ動く（しぐさで気づかない人向けの逃げ道）。当たり判定は錠剤の中だけで、
  外側の帯は `pointer-events-none` で下のページへ通す

## メモ

### 開幕（幕）との順番

幕（`components/curtain.tsx`）は `z-50` で全面を覆う。案内をそのまま出すと、初回訪問では
**幕の裏で3回動き終わってしまう**。「もう見た」かどうかは、描画前のインラインスクリプトが立てる
`<html data-curtain="seen">`（`page.tsx`）で分かるので、初回だけ `1200 + 200ms` 待ってから出す
（2回目以降は 300ms＝レイアウトが落ち着くのを待つだけ）。

高さの測定（内容 > 表示領域 + 8px）も**この待ちのあと**に行う。マウント直後だと画像やフォントで
まだ伸びきっておらず、短いページと誤判定する。

### アプリ側で作ったものの記録（差し戻し済み・再利用するなら参考に）

`useScrollHint()`（内容の高さ・表示領域の高さ・スクロール済みフラグを ref に持ち、`visible` が
変わるときだけ再レンダー）＋錠剤の表示部品という分け方自体は機能していた。判定の考え方
（「内容 > 表示領域 + 8px」かつ「まだスクロールしていない」／一度消えたら出し直さない）は
閲覧Web 版でもそのまま使える。実装は git 履歴の `d560873` にある。閲覧Web 版でも同じ判定（内容がはみ出しているか・
まだスクロールしていないか）を使っている。

### 検証したこと

`npm run lint` / `npm run build` は通った。動き・出るタイミングは実機で確かめる。
