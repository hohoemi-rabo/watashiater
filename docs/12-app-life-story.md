## メモ

### 設計判断（詳細は `app/app/story.tsx` と `app/components/curtain-overlay.tsx` の冒頭コメント）

- **幕（緞帳）**: Reanimated 4 の CSS アニメ（保存スタンプと同じ流儀）。完了コールバックが無いため、フェーズ進行（closing 900ms → closed → opening 1200ms）は setTimeout。各フェーズの「終わりの姿」を base style にして from キーフレームから滑らせる（fill-mode 不要）。translateX はピクセル値（% は挙動未保証）。reduced-motion 時はスライドなしの静的赤幕
- **開幕は閉幕完了の Promise を await してから**：レート制限 429 は幕が閉じ切る前（<1秒）に返るため。state で順序判定しない
- **生成成功・DB保存失敗**では本文を捨てない（1日3回の1回分を消費済み）。unsavedBody に保持して表示し「もういちど保存する」で upsert だけリトライ。この間は編集・再生成ボタンを隠す
- **文字回答ゼロのガード**：写真・声だけの回答でも answeredCount>0 になりホームのボタンは押せるため、この画面で body_text 非空の回答が無ければ生成ボタンを出さず案内カードにする
- 上書き確認ダイアログは `edited_by_user` のときだけ（REQUIREMENTS「編集後の再生成時は」の文字どおり）。未編集の再生成は確認なし
- 編集 TextInput は明朝18pxだが **lineHeight を指定しない**（answer 画面と同じ Android カーソル問題）。行間2.0は閲覧側のみ
- **残り回数はボタンに表示**（実機フィードバック反映）：「もういちどつくる（あと N 回）」。0回なら無効化＋「また明日」キャプション。値は worker の生成応答（429 時は 0 と確定）でしか分からないため、画面に入り直した直後は素のラベルになる。常時表示したければ worker に残数照会エンドポイントの追加が必要（MVP では見送り）
- ホームの「じぶん史をつくる」ボタンは文言・挙動とも変更なし（life_story の有無をホームで取得しない。意図的なスコープ外）
