# 30. ギャラリーの拡大表示：幕を足して、開く動きをゆっくりに

- ステータス: 進行中（実装・静的検証ずみ／実機確認まち）
- 参照: DESIGN.md §7 ギャラリー（開き方。本チケットで改訂）/ §8 モーション。実装は `app/components/photo-lightbox.tsx` と `app/lib/pleats.ts`
- 依存: 29（ひだの実装を共有する）
- 由来: クローズドテストの声（2026-09-08 ユーザー依頼「ギャラリーで写真をタップしたときのアニメーションも少し遅めに」）＋2026-09-12 のユーザー判断で**速さだけでなく幕そのものを足す**ことに変更

## 目的

「幕が中央から左右へ広がり、その前で写真が上映される」演出は 320ms では速すぎて動きが読めない。
遅くするだけでなく、29 で作った布の緞帳と同じ言語にして「幕が開いて写真が現れる」に見えるようにする。

## 決定事項（2026-09-12 ユーザー確認済み）

**速さの調整だけでなく、本物の幕を足す**（当初の「定数3つを変えるだけ」から変更）。

- 旧版の「幕」は実は幕ではなく**背景の面**（`DIMMED_SKY`）で、広がったあとも写真の地として残り続けていた。
  これを赤い緞帳にすると写真がずっと赤地の上に載ることになり、写真が主役という原則（§2）と
  1画面3色の決まり（§11-6）に反する。よって**背景の面は静止させ、その手前に幕を2枚かぶせて開く**形に改めた
- 幕は 29 とひだ（縦縞の混色グラデ）・束ね縮み（外端を支点にした translateX + scaleX）を共有する。
  共有するのは `lib/pleats.ts`（色と座標だけ）で、**幕の見た目と速さは使う側が決める**
- **金の縁・飾り幕は付けない**：写真とボタンにかぶるうえ、じぶん史と違って**写真を見るたびに毎回出る**ので、
  豪華すぎると数枚目で邪魔になる（2026-09-12 ユーザーと確認した論点）
- 所要時間：幕が開き切るまで **600ms**／写真が出るまでの待ち **320ms**／写真の立ち上がり **280ms**
- 幕は**開き切ったらアンマウント**する（写真と操作の上に居座らせない）
- reduced-motion では幕を出さない（背景の面と写真が静止で出る。従来どおり）
- 閉じる＝即アンマウントは変えない（「閉じたら音声が即止まる」が完了条件。docs/15）
- 閲覧Web の拡大表示（`web/components/polaroid.tsx` の lightbox variant）は今回対象外

## 完了条件

ギャラリーで写真をタップすると、ひだのある朱色の幕が約0.6秒かけて左右へ束ねられながら開き、その奥から写真が現れる。
開き切ったあと幕は残らない。速さと「毎回出ること」についてユーザーの了承を得ている。

## メモ

### 29 と分けたもの・共有したもの

共有したのは**2か所に置くとずれるものだけ**＝ひだの混色（`PLEAT_HIGHLIGHT` / `PLEAT_SHADOW`）、
stop 列の作り方（`buildPleatStops`）、束ね縮みの座標（`curtainGather`。transform の並び順という
間違えやすい理屈も、コメントごとここに集約した）。

共有しなかったのは幕の姿と速さ：じぶん史は金の縁＋飾り幕つきで2秒、拡大表示はひだだけで0.6秒。
共通コンポーネントにまとめなかったのは、じぶん史側が3フェーズ（閉幕→閉幕済み→開幕）を持つのに対し
拡大表示は「1回開いて消える」だけで、揃えると片方にしか要らない分岐が増えるため
（CLAUDE.md「先回りの抽象化をしない」）。

### 「重くなるのでは」への答え

ひだは View を本数ぶん並べているのではなく**グラデーション1枚**（静的なシェーダ）で、
束ね縮みは transform＝コンポジタ側。fps が落ちる作りではない。
実際の懸念は fps ではなく**毎回出ることの体感**なので、そこを 0.6秒・装飾なしで抑えた。

### 検証したこと

`npx tsc --noEmit` / `npm run lint` / `expo export --platform android` / `--platform web` は通った。
幕の重なり順（背景の面 → 写真 → 幕）と束ね縮みの座標は、同じ数値の SVG を書き出して
「開きながら写真が見えていく」ことを確認ずみ。体感の速さは実機で判断する。
