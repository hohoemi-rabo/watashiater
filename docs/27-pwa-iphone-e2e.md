## 検証結果（2026-08-14・iPhone 実機でユーザー確認）

- **Safari 通し**：ログイン → 回答 → 写真 → 録音（許可はボタン押下時・波形が動く）→
  じぶん史 → リンク発行 → 閲覧Web で表示、すべて OK
- **ホーム画面に追加 → standalone 起動 OK**（アドレスバー無し）。案内カードは Safari でのみ
  表示され、standalone では消える（表示条件どおり）
- **standalone は Safari とログインセッションを共有しない**：ホーム画面版の初回はもう一度
  ログインが必要（その場で Google ログインが通ることを確認）。**以後はアプリを閉じて
  再起動してもログイン維持**（localStorage は standalone 側に独立して持続する）
- **マイク許可も standalone で改めて求められる**（録音ボタン押下時。以後も毎回聞かれるかは
  未計測。許可は録音ボタン押下時にだけ求める設計＝チケット26 なので、聞かれても導線は迷わない）
- 上記を受けて案内カードに「ホーム画面から さいしょに ひらいたときは、もういちど ログインが
  ひつようです」の一文を追加した

## メモ

- 案内カードは `components/add-to-home-guide.tsx`（native は null スタブ）/ `.web.tsx`（実体）。
  表示条件＝iOS の userAgent かつ 非 standalone（`display-mode` と `navigator.standalone` の両建て）。
  iOS Safari に `beforeinstallprompt` は無いので手順は文字で見せる。置き場所は onboarding
  （ログイン前の初見と、せってい「つかいかたを見る」の再訪の両方で見える）
