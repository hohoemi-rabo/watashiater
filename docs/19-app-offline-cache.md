## メモ

### 中心にある契約（これ1つで画面のゲートを書き換えずに済んだ）

> **フックが `error` を立てるのは「見せるものが何一つ無いとき」だけ。端末キャッシュで
> 何か表示できているなら `error` は null のまま。**

もともとの不具合の本質はキャッシュの有無ではなく「フックが error を立てると画面が何も描かない」ことだった。この契約に変えたので `gallery.tsx` などの `!error` ゲートは1行も変えていない（`story.tsx` が既に採っていた `loadError && bodyToShow === null` の全体展開）。
さらに**キャッシュ水和を通信より先に同じ refetch 内で行う**ことで、postgrest の GET リトライ（1/2/4秒×3回。ボードは3段で最大約21秒）がスピナーごと不可視になる。supabase クライアント設定は触っていない＝オンライン時の挙動は不変。

### 判断1：キャッシュ基盤と更新戦略（`lib/offline-cache.ts`）

- AsyncStorage に `wt:v1:` 接頭辞の JSON を1リソース1キーで置く（既存の唯一の永続層・数十KB・新ネイティブモジュールを増やさない・1回の setItem で部分書き込みが起きない）。スキーマ変更は `v2` へ上げるだけ（移行を書かない）、全消しは `wt:` 前方一致で掃く
- **TTL なし**。「最後に読めた内容」を保持し、取得成功のたびに上書き
- **オンライン復帰**：`useIsOnline()` を各フックの `refetch` 依存に入れてあるので、フォーカス中の画面は復帰した瞬間に、他は次のフォーカスで自動更新。**同期キュー・書き戻し・バックグラウンド更新は作らない**（書き込みはオンライン前提＝§4.2）
- **消すのはログアウトとアカウント削除のときだけ**（家族と共用の端末に別の Google アカウントが入りうるので前の人の博物館を残さない。再ログインには通信が要るためオフライン閲覧を失う実害はない）。`Image.clearDiskCache()` も同時に呼ぶ
- **家族の博物館はキャッシュしない**（書き手が家族登録を解除しても端末に写しが残る事態を作らない）。結果として subject は常に最大1つ＝上限管理が不要

### 判断2：署名URLの扱い（「キャッシュしない」原則の唯一の例外）

- オフライン閲覧用の端末キャッシュにだけ、最後に取れた**写真の**閲覧URLを入れる。expo-image のディスクキャッシュは `cacheKey`（r2_key）で引くので、URL が期限切れでも絵がディスクにあれば通信せず描ける。逆に `uri` を undefined にすると expo-image は何も探しに行かず机の上が空になる
- 保存先はアプリ専用領域で、期限切れURLは誰の役にも立たない（1時間で失効・再発行は必ず worker の JWT 検証を通る）ため、持ち出されても新しい権限を与えない。オンライン時に毎フォーカスで取り直す原則は変えていない
- **`Image.prefetch` は `cacheKey` を受け付けない**（`ImagePrefetchOptions` は cachePolicy/headers のみ）＝prefetch 方式は不成立。実機で写真が出ない端末があれば `Image.getCachePathAsync(r2_key)` で `file://` を作る副案に切り替える
- **録音の署名URLは入れない**：声はオンライン前提（下記スコープ）で、録音の実体を端末に残さない方針（docs/00・10）も変えない

### 判断3：オフラインの認証ガードとスコープ

- 機内モードのコールドスタートでは期限切れアクセストークンにより `getSession()` が null を返し（GoTrue はネットワーク失敗ではセッションを消さない）、`/onboarding` に弾かれていた＝完了条件を壊していた。`wt:v1:auth`（userId / subject / memberships）を復元し、`restoredFromCache` のときは onboarding へ飛ばさない
- **`onAuthStateChange` を `SIGNED_OUT` 限定に修正**（`!nextSession` のままだと起動直後の `INITIAL_SESSION(null)` が復元を即座に消す）。この1点が無いと復元機構全体が効かない
- **認証の迂回ではない**：復元するのは端末内の写しだけで、サーバーへの問い合わせは従来どおり有効なトークンを要求する（セッションが無い間は問い合わせ自体を行わない）
- **声（録音再生）はスコープ外**（2026-08-12 ユーザー決定）。オフラインでは赤いエラーではなく「声は つながると 聞けます。」の案内に替える
- オフライン表示は errorRed も spotYellow も使わない（失敗でも達成でもない状況説明＝DESIGN §3）。`components/offline-note.tsx` の白カードをホーム・ギャラリー・じぶん史・回答画面の4つに出す
- 書き込みは無効化＋説明（保存・写真・録音・生成・ならべかえ・招待/リンク・ニックネーム・削除・とうろく・**ログアウト**）。ログアウトを止めるのは、オフラインでログアウトすると再ログインできずキャッシュへの入口を自分で閉じてしまうため。みたよと Google ログインは楽観更新／既存文言で足りるのでそのまま失敗させる
- 文言修正2件：じぶん史の生成失敗フォールバックとみたよ送信失敗に電波の案内を追加
